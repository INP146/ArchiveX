# 按账号设置归档内容

日期：2026-10-29。

添加账号时可以选择首次归档范围；账号详情页的“归档内容”提供三个独立选项，修改后自动保存：

- 原创帖（含引用帖）：`archive_originals`。
- 回复：`archive_replies`。
- 转发帖：`archive_reposts`，控制是否归档该账号的转发事件及其指向的原帖、媒体。

新账号和已有账号默认全部开启，保持既有行为。账号归档总开关 `archive_enabled`
继续单独控制定时同步；调整内容范围不改变账号的启停状态。

## 筛选语义

普通同步、定时同步、手动全量扫描和独立单条补档均遵循设置。同步运行开始时读取
该账号的策略；单条补档在详情解析完成后读取当前策略。正在运行的同步使用本次
启动时的设置，修改影响后续运行。

关闭某类内容后，不新增或更新该类顶层归档，也不会通过该类新内容保存被转发的
原帖和媒体。既有归档、观察关系与文件保留，既有媒体的失败重试继续执行。
已开启的引用帖、回复、转发仍按原有模型保存所需的原帖上下文，其他作者的上下文
不会因此成为该账号时间线中的独立帖子。

首次导入数量上限仅计算已选类型；被排除的条目不计入连续已知帖子停止条件。
三个选项全部关闭时，不发起时间线扫描。

补档解析到已关闭的类型后将该待补 ID 标记为 `ignored`，退出待补统计与自动重试。
重新开启类型会将此前忽略的 ID 重新置为待补，供后续同步或手动补档重新判断；
这些 ID 尚未存储正文或类型，因此也可能重新检查其他作者的 ID，作者筛选照常执行。
重新开启类型不会立即自动投递历史扫描；需要完整回补时使用“全量扫描”，仍受 X
可返回历史范围和既有队列限制约束。

## 接口与兼容

`POST /api/accounts` 可携带三个布尔字段，在提交首次同步前保存策略。省略字段时，
新账号使用默认值，已有账号保留其选择。账号解析、列表、详情及修改结果均返回策略。

`PATCH /api/accounts/{x_user_id}` 支持独立修改任意字段，例如：

```json
{"archive_reposts": false}
```

也可同时提交 `archive_enabled` 和其他选项。未提交字段不变，显式 `null` 或非法布尔值
返回 422。沿用既有认证与账号稳定 ID 校验。

`observed_accounts` 添加三个带布尔约束、默认值为 1 的列。API 存储初始化时在事务中
幂等升级已有 v3 数据库，`user_version` 保持 3；原有 v2 离线迁移规则继续适用。
无需新增环境变量。由操作者更新后端、worker 与前端并手动重启，API 初始化完成后
worker 可读取新增设置。
