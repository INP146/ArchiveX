# 手动全量扫描入口

## 使用方式

- 单账号：账号详情页点击“全量扫描”。
- 全部账号：归档账号列表页点击“全部全量扫描”。包含暂停定时归档的账号，
  仅触发一次手动任务，不修改账号的启停状态。
- 任务中心的列表及详情显示“账号全量扫描”，可查看结果、失败及重试状态。
- 已有同步任务的账号不会新建第二个任务，界面提示在现有任务结束后重试。
  全部扫描返回已提交、已有任务、提交或执行失败的数量，不把重复任务计为新提交。

## 行为及实现

`ArchiveSyncService.sync_account(..., full_scan=True)` 对本次运行关闭
首次导入数量上限及连续已知帖子停止条件；不修改共享配置，普通同步与定时同步
继续使用原来的限制。

扫描遍历 X 时间线接口可返回的分页，使用已有幂等入库及媒体任务流程。
全量扫描不保证 X 提供所有历史内容，仍受现有抓取错误处理、账号限流和任务超时
约束。没有新增历史分页断点恢复机制，也没有改变其他作者内容的筛选策略。

接口：

```text
POST /api/accounts/{x_user_id}/sync
{"full_scan": true}

POST /api/accounts/full-scan
```

普通单账号同步仍支持无请求体。全部扫描逐账号提交现有 crawl 队列，单个提交
失败不会中断其他账号的提交。所有入口使用既有认证。

任务执行参数及标签记录 `full_scan=true`。自动重试沿用任务参数；手动重跑和
批量重试失败任务也保留此模式。发布失败回滚时保留参数，避免后续重跑退化为
普通同步。全量扫描和普通同步共用账号任务锁，不增加同账号并发。

- 当前工作区后端测试：196 项通过。
- 前端 TypeScript 检查及 Vite 生产构建通过。
- 回归测试覆盖首次/增量上限绕过、普通同步配置保留、单账号/全部账号接口、
  暂停账号、认证、批量提交部分失败、共享任务锁、worker 参数传递、
  发布失败参数保留，以及手动重跑/重试的全量模式保留。
- 未启动、停止或重启服务，未向生产队列投递扫描任务。

操作者需更新包含本次代码的后端和前端镜像，手动部署后入口才在生产生效。
无需修改环境变量或数据库 schema。
